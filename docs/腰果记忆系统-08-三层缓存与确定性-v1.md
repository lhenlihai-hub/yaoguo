# 腰果记忆系统 08：三层缓存与确定性 v1

状态：已接入唯一 Agent 会话、指令记忆、系统 Prompt section 与 Compact 入口
所有者：`src/platform/memory/cache/`、`src/platform/memory/instructions/`、`src/platform/ai/`

## 一、目标

记忆缓存不是一个全局开关，而是每个任务会话拥有的三份独立 `Map`。每层缓存不同产物、单独计数和失效；清除一层不会暗中联动其他层。

缓存机制由宿主确定性执行。模型仍负责判断规则如何应用、信息是否值得保存、哪些长期记忆相关，以及 Dream 如何整合；模型不能自行选择缓存作用域、伪造失效点或绕过当前快照。

## 二、三层缓存

| 层 | Map | 缓存产物 | 首次计算 |
|---|---|---|---|
| 1 | `memoryFiles` | 指令文件读取、Front Matter、HTML 注释剥离、`@include` 展开及诊断 | 首次发现或按路径激活 |
| 2 | `userContext` | 有效规则正文、最终 `<system-reminder>`、digest、来源摘要与当前日期 | 当前任务会话首次装配 |
| 3 | `systemPromptSections` | system prompt section 的稳定字符串；key 是 section 名 | 当前任务会话首次请求该 section |

任务会话 key 由宿主从规范 `projectId + taskId` 生成。不同任务即使访问同一个仓库，也不共享用户上下文或 system section Map；应用重启后进程内缓存自然消失。

### 第 1 层：memoryFiles

`InstructionFileLoader` 在检查普通文件、硬链接、符号链接、大小与作用域后读取一次。成功值、空结果和稳定诊断都进入 Map。缓存命中不再读取 stat，也不比较 mtime、ctime、大小或 inode；因此原文件、Front Matter 与 include 文件在本会话内形成同一个不可变观察结果。

HTML 注释在解析阶段移除，不进入规则正文。动态子目录规则仍可在工具首次访问该目录时按需发现；这是新的路径激活事件，不是文件热重载。已经发现并缓存的文件不会因磁盘修改自动变化。

### 第 2 层：userContext

该层保存已经选择、排序和预算裁切后的规则状态，并缓存：

- 最终 Markdown 正文组合；
- 首条 `user` message 使用的 `<system-reminder>`；
- 当前有效顺序、digest、Token 与诊断；
- 宿主本地日期 `YYYY-MM-DD`。

跨过午夜不会自动改变已缓存日期。只有全量失效后的下一次装配才取得新日期。工具访问新目录后允许把新激活规则合并进此层；下一轮对话从更新后的确定性快照开始。

### 第 3 层：systemPromptSections

每个任务会话拥有独立 Map，使用 section 名作为 key。`memory.behavior` 首次成功加载后在本会话复用；用户规则文件和长期 Memdir 的变化不会重算该 section。空值与损坏的必需 section 不缓存，仍然 fail-closed。

## 三、失效矩阵

| 操作 | memoryFiles | userContext | systemPromptSections |
|---|---:|---:|---:|
| `/memory` | 清除 | 保留 | 保留 |
| `/clear` | 清除 | 清除 | 清除 |
| 请求级 Compact | 清除 | 清除 | 清除 |
| Session Memory Compact | 清除 | 清除 | 清除 |
| 手工修改磁盘规则 | 保留 | 保留 | 保留 |

`/memory` 只清第 1 层，所以模型仍看到第 2 层已经拼接好的旧用户上下文；它不是规则热重载命令。`/clear` 与 Compact 才建立下一阶段的完整装配边界。

Compact 清缓存发生在压缩边界和摘要已经确定之后。当前正在发送或生成的模型请求继续使用原快照；新规则只可能从下一次上下文装配生效。

## 四、没有规则文件热重载

运行链路不注册 `fs.watch`、`watchFile` 或通用目录 watcher 来刷新 `YAOGUO.md`、`YAOGUO.local.md`、`.yaoguo/rules/**/*.md`。未来若团队记忆同步使用文件 watcher，该 watcher 只报告同步状态，不得调用三层缓存失效接口。

用户在会话中途用编辑器修改规则文件时，在对应缓存失效前：

1. 已开始的模型响应不改变；
2. 下一轮仍使用旧的用户上下文；
3. system memory section 也保持原值；
4. 不会因 mtime 变化产生隐式规则切换。

这牺牲即时更新，换来一个可审计的不变量：同一缓存阶段中的规则、日期和系统记忆规范保持确定。

## 五、并发与命令边界

`/clear` 和 `/memory` 是宿主缓存控制命令，不发起模型调用。它们进入任务级串行执行器；若当前 Agent turn 尚未结束，命令在其后执行，不能在流式响应中途替换规则。

三层 Map 原地 `clear()`，已持有引用的当前执行仍能完成；后续装配看到递增的 generation 与空 Map。各层 generation 独立，便于测试失效是否发生在正确边界。
