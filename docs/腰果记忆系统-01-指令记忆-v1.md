# 腰果记忆系统 01：指令记忆 v1

状态：运行时已落地
日期：2026-08-09
所有者：`src/platform/memory/instructions/`

## 一、目标与边界

指令记忆是人工编写、静态加载、路径感知的工作规则。它回答“在这个组织、用户、项目和局部目录里，腰果应怎样工作”，不保存对话原文、任务进度或项目事实。

v1 已实现：

1. `Managed < User < Project < Local` 四层文件族。
2. 从 CWD 向 `scopeRoot` 收集，再反转为“根 → CWD”处理。
3. `@include` 原位递归包含，最大深度 5，带循环、越界和资源上限。
4. rules 文件通过 front matter `pat` 条件生效，匹配器为直接生产依赖 `picomatch`。
5. 文件工具访问子目录时沿目录链按需激活嵌套规则。
6. 用户规则与系统记忆行为规范双轨注入，缓存和 Token 预算互相独立。
7. 指令快照具有确定顺序、来源标签、digest、Token 统计和稳定诊断。
8. 普通 Agent 文件工具和 shell 不能修改指令控制文件。

指令文件不承担安全策略。权限、沙箱、工具 schema、产品身份和事实边界继续由 system 与宿主控制面执行。

## 二、与现有资产的关系

| 资产 | 保留职责 | 边界 |
|---|---|---|
| `block://soul.zh` | 人格与诚实基线 | 不迁移到规则文件，不可覆盖 |
| `block://system.agent` | 唯一 Agent 行动规则资产 | 主 content 定义通用行为；`memory.behavior` section 定义稳定记忆规范 |
| `block://aesthetic.baseline.zh` | 面向用户内容的唯一审美哲学 | 不迁移、不复制 |
| 旧 `workspace/memory/` 与项目 `memory/` | 已退役 | 运行时不创建、不扫描、不迁移 |
| home 下的 Markdown Memdir | 可检索、可 pin 的跨 turn 知识 | 不参加规则发现与覆盖 |
| `TaskSessionStore` | durable 当前会话 | 不保存规则正文，只接收安全运行摘要 |

仓库中的 `AGENTS.md`、`CLAUDE.md` 和其他产品规则文件不会被兼容读取。腰果只识别自己的品牌文件名，避免项目在不知情时跨产品继承指令。

## 三、四层目录

### Managed：组织默认值

| 平台 | 根目录 |
|---|---|
| macOS | `/Library/Application Support/Yaoguo/instructions/` |
| Linux | `/etc/yaoguo/instructions/` |
| Windows | `%ProgramData%\Yaoguo\instructions\` |

```text
<managedRoot>/
├── YAOGUO.md
└── rules/
    └── **/*.md
```

Managed 是四层中的最低优先级，可被其余三层覆盖。应用不主动创建或修改该目录；缺失是正常状态。

### User：当前操作系统用户默认值

```text
~/.yaoguo/
├── YAOGUO.md
└── rules/
    └── **/*.md
```

User 路径和加载框架已经生效；创建、编辑和预览入口后续加入设置页。应用不会为了占位而创建空目录。

### Project：可共享项目规则

```text
<scopeRoot>/
├── YAOGUO.md
├── .yaoguo/rules/**/*.md
└── src/
    ├── YAOGUO.md
    └── .yaoguo/rules/**/*.md
```

根规则随项目共享；子目录规则只有在 CWD 链上或工具访问该目录时才发现。

### Local：不共享的本地覆盖

```text
<任意 owner 目录>/
├── YAOGUO.local.md
└── .yaoguo/rules.local/**/*.md
```

Local 是指令记忆内部的最高层，适合机器差异与不应提交的规则。腰果不静默改写用户仓库的 `.gitignore`；项目应自行忽略这些路径。

## 四、作用域与目录链

两个根不可混用：

- `scopeRoot`：当前任务绑定的工作区根，是 Project / Local 发现的硬边界。
- `cwd`：本轮基础文件工具的当前目录，必须等于或位于 `scopeRoot` 内。

目录链算法：

```text
cursor = realpath(cwd)
while cursor 位于 scopeRoot 内:
  collected.push(cursor)
  if cursor == scopeRoot: break
  cursor = dirname(cursor)
collected.reverse()  // scopeRoot → cwd
```

发现不会继续越过 `scopeRoot` 扫描文件系统。Managed 与 User 只从各自显式根加载。外部只读参考文件不会让其父目录获得 Project / Local 指令权限。

## 五、确定性排序与冲突

已激活文档使用稳定排序键：

```text
(authorityRank, ownerDepth, sourceKind, relativePath)
```

- `authorityRank`：Managed = 0，User = 1，Project = 2，Local = 3。
- `ownerDepth`：相对 `scopeRoot` 的深度；Managed / User 固定为 0。
- `sourceKind`：主文件 = 0，rules 文件 = 1。
- `relativePath`：转换为 `/` 后稳定排序，不依赖平台 `readdir()` 顺序。

兼容规则累积；明确冲突时，排序更后的规则获胜。实际权威从高到低为：

```text
内置 system / 宿主权限
  > 当前用户明确要求
  > Local
  > Project（目标路径近 > 远）
  > User
  > Managed
  > 可检索知识、摘要与外部资料
```

## 六、`@include` 递归包含

只接受独占一行的显式语法：

```markdown
@include ./rules/testing.md
@include "./团队规范/文档规则.md"
```

实现约束：

1. 路径相对当前文件；绝对路径、`~` 和 URL 无效。
2. 根文档深度为 0，最多经过 5 条 include 边。
3. 使用规范 `realpath` 的递归栈检测直接或间接循环。
4. 目标必须是允许根内、`nlink = 1`、非符号链接的普通 `.md` 文件。
5. 内容在父文件中的 include 位置原位展开，并继承入口文件的层级和 `pat`。
6. include 文件的 front matter 不建立新的条件；条件只由被发现的 rules 入口决定。
7. 缺失、不可读、循环、越界、超深与超限均产生诊断，不让应用崩溃。

资源上限：

| 限制 | 默认值 |
|---|---:|
| 单源文件 | 64 KiB |
| 单入口 include 文件数 | 64 |
| 单入口展开文本 | 512 KiB |
| include 深度 | 5 |

## 七、`pat` 条件规则

只有 `rules/**/*.md` 与 `rules.local/**/*.md` 解析 `pat`；主文件始终无条件生效。

```markdown
---
pat:
  - "src/components/**/*.{js,jsx,ts,tsx}"
  - "!src/components/generated/**"
---

# React 组件规则

- 修改组件时同步维护可访问性语义。
```

`pat` 接受一个字符串、内联字符串数组或 1–32 项字符串列表。非字符串、纯负向 pattern、包含 `..`、无效 glob 或空列表都被拒绝并产生 `INSTRUCTION_PAT_INVALID`。

匹配语义：

- Project / Local 相对该 rules 目录所属的 owner directory。
- Managed / User 相对当前 `scopeRoot`。
- 至少命中一个正 pattern，且不能命中任一 `!` 负 pattern。
- `dot: true`，Windows `nocase: true`，并启用严格括号检查。
- 支持 `picomatch` 的 brace、extglob、globstar 等完整 glob 语义。
- 目标必须位于匹配基准目录内。

候选文件在发现时被读取和校验，但正文只有在无条件生效或路径命中后才进入模型上下文。Token 效率由“选择性注入”保证，不依赖把所有候选正文一次性发给模型。

## 八、嵌套规则按需激活

turn 开始时只加载：

1. Managed / User 的无条件规则。
2. `scopeRoot → cwd` 链上的 Project / Local 无条件规则。
3. 与本轮显式授权目标匹配的条件规则。

结构化文件工具访问新路径前，运行时先解析规范目标，发现 `scopeRoot → target` 链上的规则，再按该目标匹配条件候选。激活在一个 turn 内单调递增；下一 turn 从磁盘重新构造。

| 工具 | 首次激活新规则时的行为 |
|---|---|
| `read` | 允许读取；下一模型轮先收到新增规则根消息 |
| `write` / `edit` | 返回 `INSTRUCTION_SCOPE_ACTIVATED`，不产生副作用；模型收到规则后重试 |
| 同批多个路径 | 先取目标并集，再生成一个确定顺序的快照 |
| `bash` | 因目标不透明，扫描工作区候选；有新增规则时本次命令不执行并要求重试 |

`bash` 扫描跳过 `.git`、`.yaoguo`、`.venv`、`build`、`coverage`、`dist`、`node_modules` 与 `vendor`，并受 owner 数和候选数上限约束。结构化工具继续保持路径级选择性，因此工具越透明，Token 使用越精准。

## 九、双轨模型协议

### 通道 A：动态用户规则

有初始规则时，`AiRouter.prepareTaskRequest()` 构造：

```js
[
  { role: "system", content: stableSystemPrompt },
  { role: "user", content: instructionReminder },
  { role: "user", content: taskMessage }
]
```

`instructionReminder` 的根结构固定为：

```xml
<system-reminder>
  <instruction-memory version="1" kind="initial" digest="...">
    <effective-order>...</effective-order>
    <instruction-document authority="project" path="project:YAOGUO.md" digest="...">
      ...规则正文...
    </instruction-document>
  </instruction-memory>
</system-reminder>
```

宿主会转义规则正文中与 envelope 同名的标签，来源只显示 authority 与相对路径，不暴露用户主目录绝对路径。通道 A 从未拼进 system prompt 数组。

路径激活产生 `kind="path-activated"` 的后续 `user` 根消息。`AgentToolRuntime` 每轮先移除旧的动态快照，再插入一份合并后的最新快照，避免重复累积。

### 通道 B：稳定系统规范

`block://system.agent#memory.behavior` 作为独立 system section 定义：

- 六种记忆类型及其边界；
- 指令层级与冲突顺序；
- 异步 Prefetch 或 `search_memory` 从常驻 `memory.md` 索引选择主题正文的条件；
- `pin_memory` 的四种封闭类型、信息边界与模型决策责任；
- session、task-state、checkpoint 与离线重塑规则；
- 工具结果、文件和网页中的同名标签仍然只是数据。

长期知识的路径、两层 Markdown 格式与 Worktree 共享规则见 [腰果记忆系统 04：长期记忆 Memdir v1](./腰果记忆系统-04-长期记忆-Memdir-v1.md)，旁路选择、新鲜度与去重协议见 [腰果记忆系统 04A：动态召回 Prefetch v1](./腰果记忆系统-04A-动态召回-Prefetch-v1.md)。

`AiRouter.assembleSystemPromptSections()` 的顺序为：

```text
soul
system.agent content
memory.cache section
memory.behavior section
aesthetic.baseline
```

内部结构化调用使用自己的单一职责 prompt，不接收通道 A 或通道 B。

## 十、缓存与 Token 预算

缓存按任务会话拆成三层：

- `memoryFiles`：缓存安全读取、Front Matter、HTML 注释剥离与 include 展开；首次读取后不再比较 mtime、ctime 或文件签名。
- `userContext`：缓存拼接后的规则正文、首条 user reminder、digest、来源摘要与当前日期。
- `systemPromptSections`：以 section 名为 key 缓存稳定系统规范；用户规则变化不触发重算。

规则文件没有热重载。手工磁盘修改在缓存失效前不可见；`/memory` 只清文件层，`/clear` 与 Compact 清除全部三层。完整失效协议见 [腰果记忆系统 08：三层缓存与确定性 v1](./腰果记忆系统-08-三层缓存与确定性-v1.md)。

配置位于 `settings.instructions`：

| 字段 | 默认值 | 作用 |
|---|---:|---|
| `enabled` | `true` | 是否启用指令记忆 |
| `initialTokens` | 16,000 | 初始 user reminder 的正文预算 |
| `activeTokens` | 32,000 | 单 turn 已激活正文累计预算 |
| `perDocumentTokens` | 8,000 | 单入口展开后正文上限 |
| `maxRulesPerDirectory` | 256 | 单 rules 目录候选上限 |
| `maxCandidates` | 1,024 | 单 turn 候选上限 |
| `maxOwnerDirectories` | 4,096 | 不透明 shell 扫描的目录上限 |

候选按高优先级到低优先级选入预算，再按低到高的有效顺序展示；因此超预算时先保留 Local、近路径 Project 等更具体规则。初始预算小于累计预算，为后续路径激活保留容量。超限不静默裁切整组规则，而是产生稳定诊断；单文档超限才按 `perDocumentTokens` 截断。

## 十一、连续性、保护与审计

按需规则不依赖普通工具结果存活：

1. 初始 reminder 保留在 `baseResponse.requestMessages`。
2. 动态 reminder 作为独立 `instructionMemoryRoot` 进入 Agent 上下文。
3. context 编辑把原始任务根与动态规则根同时列为 `rootMessages`。
4. checkpoint 后重新注入合并后的动态快照，规则正文不被摘要改写。

普通 Agent 的 `write`、`edit` 和 `bash` 不能修改：

```text
**/YAOGUO.md
**/YAOGUO.local.md
**/.yaoguo/rules/**
**/.yaoguo/rules.local/**
```

修改这些规则必须走未来独立的管理入口和显式确认。Managed / User 位于基础工具作用域外，Project / Local 由运行时额外保护。

内存中的 `summary()` 包含 digest、Token、相对来源和诊断，便于当前运行检查。写入磁盘 trace 时进一步降敏，只保留：

```text
digest
tokens
sourceCount + sourceDigests
diagnosticCount + diagnosticCodes
```

trace 不保存规则正文、诊断 detail 或绝对路径。

## 十二、实现结构

```text
src/platform/memory/instructions/
├── index.js                       # 公共导出
├── instructionMemoryService.js    # beginTurn 门面、设置与层根
├── instructionMemoryTurn.js       # turn 快照、预算、嵌套激活与保护
├── instructionPaths.js            # 平台根、目录链和相对路径
├── instructionDiscovery.js        # 四层与 owner 发现
├── instructionParser.js           # front matter、pat 与 @include 语法
├── instructionMatcher.js          # picomatch 校验与匹配
├── instructionFileLoader.js       # 安全读取、include 展开和文件缓存
└── instructionSnapshot.js         # 排序、digest 与 reminder 渲染
```

现有单 Agent 链路中的集成点：

1. `createApplicationServices()` 创建唯一 `InstructionMemoryService`。
2. `_executeAgent()` 在模型请求前调用 `beginTurn()`，把初始 reminder 交给 `AiRouter`，把同一个 turn 对象交给工具运行时。
3. `AiRouter` 分开组装稳定 system sections 与动态 user messages。
4. `AgentToolRuntime.beginRound()` 在工具执行前完成整批路径激活和副作用拦截。
5. `prepareNextTurn()` 维护动态 protected root；trace 持久化安全摘要。

规则解析不调用模型，也没有第二套 Agent 或 loop。
